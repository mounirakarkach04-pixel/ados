01 / DEVICE DATA

Lokale Datenbestände

Die vorhandenen Testdaten aus der älteren Browserspeicherung werden beim ersten Öffnen automatisch übernommen. Es wird nichts in die Cloud übertragen.

Datenbank wird geöffnet …

Browserdaten können bei Geräteschaden, Zurücksetzen oder Löschen der Website-Daten verloren gehen. Verschlüsselte Sicherungen sind deshalb wichtig.

02 / BOUNDED EXECUTION

Lokale Worker

Auftrag wählen, dauerhaft in IndexedDB hinterlegen und auf diesem Gerät ausführen. Keine Druckbefehle, Diagnosen oder externen Netzwerkaktionen.

Bereit.

03 / DEVICE TO DEVICE

Verschlüsselter Datentransfer

Ohne Cloud: Auf Gerät A verschlüsselt exportieren, Datei sicher auf Gerät B übertragen, dort wieder importieren. Keine automatische Synchronisierung.

AES-GCM und PBKDF2-SHA256 · nur auf diesem Gerät entschlüsselt.

Beim Import werden beide lokalen Testdatenbestände auf diesem Gerät ersetzt. Erst eine eigene aktuelle Sicherung erstellen.

04 / GOVERNANCE

Grenzen der lokalen Architektur

  • Smartphone, Tablet und Desktop verwenden denselben Web-Code, aber getrennte Gerätespeicher.
  • Es gibt keine Berechtigungsverwaltung durch Supabase oder einen anderen Cloud-Anbieter.
  • Worker arbeiten während einer aktiven Sitzung. Ein dauerhaft laufender Hintergrundprozess ist im Browser nicht garantiert.
  • Keine echten Patientenakten oder vertraulichen Personalunterlagen in diese offene Evaluation eintragen.
  • Synchronisierung mehrerer Geräte braucht später einen geprüften Transport, Konfliktbehandlung und Datenschutz.
